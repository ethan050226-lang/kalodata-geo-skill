# 核心发现分析

运行 Agent 负责判断本批最值得关注的事实，工具负责核对范围、批次及分子分母。无需新增模型服务或密钥。数值校验不代替 Agent 对结论与证据的审核。

## 同批分析与发布

1. 完成题库核对、回答匹配、质量筛查和国家模型裁剪。中国只纳入已确认七模型，不因历史记录中有 Perplexity、Gemini 或 AI Mode 就纳入分析。旧看板没有 `model_policy` 时先从同批母库和对应题库生成合规副本；不能只改文字或删掉某个模型名字。
2. `geo_run.py` 返回 `local_ready_pending_analysis` 时，Agent继续读取返回的私有上下文。其他入口或缺少上下文时运行 `python3 core_findings.py context <看板.html> <上下文.json>`。这一步不联网、不重新取数。
3. 读取 `required_scopes`、行维度、指标及代表回查记录；分别分析总体及每个国家，可增加平台、题类或其他筛选组合。结论简短写清“哪里、什么指标、多少、下一步”，每句话由本批数据支持。分子分母紧邻数字，时间放对应范围，不长段复述。低比例不自动等于最优先的问题，不自行设样本阈值。证据不足只列具体待核查对象；删除泛化提醒。缺失和不可比写成带实际原因、数量的状态，集中到数据提醒；方法和解释边界集中到指标说明，同页只提示一次。
4. 写一个私有 JSON，顶层仅有 `version`、`data_sha256`、`entries`。前两项照上下文；每个 entry 仅含 `row_indices`、`conclusion`、`judgment`、`metrics`。行号取同批 `index`，升序去重；`metrics` 使用对应所选行重新合计的 `mention`、`first`、`negative`、`mixed` 四个 `[分子,分母]`。`conclusion`写简短数据事实，`judgment`写具体下一步；证据不足以“待核查”开头，无可定位对象可为空。只有一个国家时总体与该国为同一行集合，只写一次。原文、凭证和本机查询地址不写入。
5. 执行 `python3 core_findings.py apply <看板.html> <分析.findings.json>`。数据校验值、行范围、指标或国家覆盖不一致时停止写入，原看板保留。成功后使用同一 HTML 和数据库继续 `feishu_publish.py`；不得重跑 refresh 来补分析。正式发布、权限与交互验收仍沿用原规程，定时任务保持暂停。

## 筛选行为

- 当前选中样本集合与 Agent 某条分析完全一致时显示该条；国家范围变了不能继续显示另一国家或全批分析。
- 日期、平台、分组、标签和点名状态变化后，没有同样本集合的分析时仅展示当前范围指标；在数据提醒标“待分析：当前筛选无专项结论”，不重复提示或编造分析。
- 未按国家模型校验的旧批停止展示核心发现和行动，提示重新生成；缺数据不填零，不把未检出写成确定不存在。
- 简报采用同批总体分析；各国结论保存在看板中。发布版本指纹包含分析结果，修改分析需重新验收候选，不能沿用旧验收凭证。
