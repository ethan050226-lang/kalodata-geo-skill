# 飞书题库连接：检查、复用与开通

适用于首次安装、换 Agent/运行环境、题库连接失败。目标是复用已获批的最小只读连接；不是为每个 Agent 重建应用或重新登录。安装 Skill 不会自动获得飞书权限。

## 每次运行的顺序

1. **先找现有连接。** 检查当前 Agent 实际可调用的表格/知识库工具，以及公司在本运行环境已配置的官方 CLI。复用已保存、获准访问当前题库的应用和身份；不要扫描其他用户的密钥、借用账号、覆盖公司连接或重复创建应用。只读 Key 就绪后才读取私有品牌资源和题库地址，实际值不进入公开仓库、常规日志或看板。
2. **核对当前身份与登录态。** CLI 可用 `lark-cli auth status --json --verify`，只取身份、登录状态和权限等必要字段，隐藏令牌及私人配置。已有获批应用连接可用时直接复用，不要求个人再扫码。已有获批用户连接时沿用其身份，不默默改用另一个账号或应用。
3. **实读验证，而不是只检查配置。** 内建入口 `feishu_bank.fetch_bank` 每次从线上读取完整题库，检查国家工作表、行列完整、前后修订一致及题号，再原子更新缓存。可先运行 `python3 feishu_bank.py .trial/在线题库.xlsx` 验证连接；题库地址来自获批环境的 `GEO_QUESTION_BANK_URL`。CLI 的 `ok:true`、`preflight_only`、登录成功、题库标题可见均不代表完整读取通过。成功回执至少包含读取时间、修订号、国家页数、有效题数及一个题号，不输出整库。
4. **验证后继续完整运行。** 在线题库通过后继续 `geo_run.py` 的真实刷新，不再次索要已保存且有效的资料，不停在预检。当前授权/权限检查失败时不请求 Answerbit，不回退旧题库；上一份成功结果继续保留，并明确其原日期。

原生工具与 CLI 要分开检查：单篇文档工具不一定能读表格，某个工具报错也不代表全部工具都不可用。当前仓库内建的是 CLI 读取路径；`fetch_bank(..., read=...)` 允许注入读取函数，但原生工具须适配并验证相同的完整网格、元数据及修订契约，才能接入。没有适配器时如实报告，不能只凭 Agent 看到了几行就声称脚本已连接，也不能用旧 Excel 绕过在线核对。

## 沿用已批准的身份

内建工具复用当前 CLI 配置的应用及凭证，不创建应用、不自动登录。

- 默认明确使用 `bot`，保持现有应用连接行为。
- 公司已配置并批准使用用户只读连接时，在该运行环境的私有配置中设置 `GEO_FEISHU_BANK_IDENTITY=user`；应用连接可设为 `bot`。只允许这两个值，不能设 `auto`。这是题库读取身份，与飞书看板发布配置的 `identity` 分开。
- 同次题库结构和单元格读取使用同一身份。遇到权限失败不得静默换身份重试；确需切换时先核验新身份已经获准访问该题库，再保存选择。
- 其他 Agent 复用同一获批应用、同一题库访问范围时，应用权限通常不必重新申请，但每个运行环境仍需有获准的连接配置，并实读验证。换应用、账号或题库须重新核验；不复制个人令牌，也不把密钥写入 Skill。

## 失败时按原因处理

先给用户「哪里失败、影响什么、谁来处理、下一步」，技术细节仅给管理员。只读诊断不得扩大权限或发起新授权。

| 实际情况 | Agent 应该做什么 |
| --- | --- |
| 没有可用读取工具或缺 Excel 组件 | Agent 检查现有环境、依赖及获准安装方式；需要运行平台管理员处理时说明。不能让用户提交程序库，也不能把组件问题说成需要企业审批。 |
| 应用未开通权限，例如 `app_scope_not_applied` / `99991672` 并列出缺失项 | 核对失败接口、当前应用、身份及本次 `missing_scopes`。进入该应用的官方权限入口，按下面的开通流程处理；不要反复个人扫码。 |
| 用户连接无登录凭证或失效，例如 `token_missing` | 先核对应用已经开通所需权限，再引导本人完成官方用户授权。只授权必要范围；链接和二维码来自本次官方响应，不复用过期链接，不在聊天索取令牌。 |
| 用户已登录但 `missing_scope` | 区分应用尚未开通，还是用户授权未覆盖。应用未开通时个人同意无法替代；应用已开通后才补最小用户授权。 |
| 文件不可访问 | 核对同一身份是否拥有指定题库的可阅读权限，由文件负责人按需分享。文件编辑权限不能替代应用权限，不要求编辑或管理权限。 |
| 表格不存在、链接类型或内容异常 | 核对 Wiki 节点与底层表格类型及标识，不仅凭长度或 dry-run 判定链接错误；实际失败后用已有权限解析节点。缺额外权限仍先报告，不自动申请。 |
| 网络错误、响应格式变化、缺表、截断或版本中途变化 | 单列网络/结构/完整性原因。允许一次有依据的恢复或重新读取；同一错误未发生配置或权限变化时停止重复尝试。 |

`missing_scopes` 可能是“必须这一项”，也可能是“多个权限满足其一”，须按当前接口的原始错误和官方说明选择最小只读项，不把全部候选都申请。当前 CLI 的 `sheet_ai ... invoke_read` 若明确要求 `sheets:spreadsheet:read`，按这一项核实；不能机械套用其他接口可接受的 `sheets:spreadsheet:readonly`，更不能据此要求写入权限。

## 缺权限的具体开通步骤

1. 使用当前失败响应中的官方 `console_url`，或到飞书开放平台 → 当前应用 → 权限管理，找到本接口要求的最小表格读取项。不要使用其他 Agent 的私人应用链接，也不要在公开说明中写入真实应用 ID。
2. 将应用、所需只读权限名称、题库范围、用途及页面实际要求告诉用户。页面若标「免审」，说明无需先假定企业管理员审批，但新增数据访问仍须用户确认后才能开通；不要把免审说成自动授权。
3. 获准后只选本次必要项。**不要勾选“一并开通其他权限”或“全部权限”**，不修改文件分享、不申请写权限。页面确实要求企业管理员审批或发布版本时，先报告并等待用户决定；不顺带提交其他未获准变更。
4. 回读页面结果。只有出现成功状态才说已开通；若需审批/发布未完成，明确待生效。通过工具的正常方式刷新现有凭证，不把令牌发送到对话。
5. 用同一应用和身份重读同一题库，完成全部国家页校验并给出实际回执。只有实读通过，才继续 Answerbit 取数；页面开通成功不等于整条数据链路验收完成。

失败仍保留原状态及上一成功批次。向用户一次性列出当前真正缺项；缺少新证据时不重复要求登录、申请同一权限或恢复旧定时任务。题库授权不意味着看板发布、收件人范围或消息权限也已获得。
