# 默认飞书交付：版本核对 → 复用 / 上传 → 验收 → 链接与简报

## 管理员一次配置

使用现有官方 `lark-cli`，不自建托管或数据库服务。Answerbit 品牌级只读 Key 与飞书身份授权独立，凭证保存在获批环境/钥匙串。私有环境配置 `GEO_QUESTION_BANK_URL`、必要时的 `LARK_CLI` 及 `GEO_FEISHU_CONFIG`（JSON 文件路径）。配置文件例：

```json
{
  "folder_url": "https://company.feishu.cn/drive/folder/FolderToken",
  "identity": "bot",
  "sharing_scope": "admins_only",
  "approved_members": [
    {"member_type": "openid", "member_id": "ou_approved_admin"}
  ],
  "state_dir": "/private/path/geo-publication"
}
```

只填实际批准管理员；identity可省略或留空，默认bot，既有user配置保持不变，无需向用户索要技术字段。精确匹配成员类型与 ID，不用姓名推断身份，不把群组/部门当作已验证的个人访问范围。普通运营账号未完成允许/禁止范围测试前，名单中不得加入运营范围。文件夹、成员 ID、旧成功链接等均只存私有配置，不提交公开仓库。可选 `previous_success` 保存有依据的旧入口、batch 及验收时间，**只作失败回退提示，不参与版本去重**。旧入口本次未核验时必须注明。

`sharing_scope` 默认 `admins_only`，保留旧配置行为；用户明确选择公司内共享后，可在私有项目配置设为 `tenant_readable`。此模式表示同公司登录并获得链接的人可阅读本批获准内容，不是互联网公开，也不是按国家隔离权限；筛选不能阻止阅读 HTML 内的其他已共享国家。首次变更须展示准确的新文件、当前与目标设置，确认后仅改该文件为组织内链接可阅读、禁止外部访问，不改父目录或旧版，不自动添加协作者。代码不静默修改分享权限。验收 JSON 清单仍只限批准管理员及应用，不能随看板开放。

应用仅申请实际需要的目录枚举、文件上传/下载、元数据、权限设置读取及成员读取权限；另核对获批目录的资源访问权；应用scope本身不等于只开放一个目录。需要企业管理员审批时，必须先按[权限申请前置报告](../SKILL.md#权限申请前置报告)向用户报告并等待决定，不自行申请或扩权。使用官方CLI在已批准的目录及接收范围内发布，不自动新增接收者或扩大分享。禁止用完整云盘授权绕过缺权限。新建上传可能自动给当前 CLI 用户管理权，该用户也必须在批准名单内。

## 一次列清发布权限

先复用当前运行环境已有的获批连接，核对实际应用名称、app_id与bot/user身份（ID仅放管理员详情）。不要以Codex本机另一个应用的失败推断运行Agent缺权限。`lark-cli auth scopes --json`可只读查看当前应用权限；按当前CLI实际结构读取`scopes`/`userScopes`及`tokenType`，用户授权清单不能冒充bot权限。查询失败标未知，不能当作全部缺失。

使用官方[larksuite/cli](https://github.com/larksuite/cli)及其随附说明；原生调用前先看schema。启动时汇总下表全部能力，区分“已配置”“实际读通过”“缺失”“未验证”；只读探测不上传测试业务文件，不为确认权限而修改分享。可运行：

```sh
python3 feishu_publish.py <已有看板.html> <已有库.sqlite> --check-access
```

此命令不读Answerbit、不读取或改写批次、不上传、不改权限；目录、协作者、分享设置逐项探测，一项失败也继续收集另外两项。写入能力统一标未验证，须结合实际应用清单核对；读通过不证明上传或下载通过。配置缺失先定位缺项，不能臆造连接。

| 能力 | 优先核对的最小权限 | 处理边界 |
| --- | --- | --- |
| 列目录、查已有版本 | `space:document:retrieve` | 本次租户实测需企业审核；其他环境以后台当时标记为准，申请前先报告。 |
| 上传共享HTML/私有回执 | `drive:file:upload` | 本次实测免审，新增仍须用户确认。 |
| 下载原文件、核对SHA-256 | `drive:file:download` | 明确指定相对输出文件，避免为默认命名额外申请元数据权限。 |
| 读取直接及继承协作者 | `docs:permission.member:retrieve` | 文件与父目录分别核对；不把应用scope当资源共享权限。 |
| 读取分享设置 | `docs:permission.setting:read` | 核对实际链接范围与外部访问，不能只看上传成功。 |
| 修改分享设置 | `docs:permission.setting:write_only` | 仅用于已确认的具体新文件，父目录和旧版不改。 |
| 新文件保留管理员访问（按需） | `docs:permission.member:create` | CLI以bot新建可能尝试给当前CLI用户full_access；核对该用户在批准名单内，不转移所有者。 |

上表后六项在本次后台实测免审，不保证其他租户或后续平台规则相同。旧版CLI、导出权限核查或特定资源可能额外要求`docs:permission.member:auth`等条件权限：先核对CLI版本、官方错误和接口实际需要，单列原因与最小权限，再向用户报告；不能从一次报错猜测“文件不支持”或直接补全量权限。已有获批等价权限可复用，官方错误里的N选1不是全部都要申请。

一次给用户“问题、影响、处理人、下一步”，管理员详情列最小scope、当前状态、官方入口、是否需企业审批（查不到写待核实）、资源范围及替代路径。应用未开通、用户未登录、文件未共享、工具/网络异常分开说明。需要企业审核的权限，在申请、扩权、提交审核或发布权限版本之前先报告并等待决定；仅允许免审时不提交审核项。免审不代表可无确认新增访问权。不要重复扫码、借用其他账号或改用`drive:drive`等宽权限绕过问题。

## 界面辅助单次发布

CLI连接或目录权限暂未齐全，但用户允许单次发布、已登录的飞书界面可访问获批目录时，按本次已验证路径处理。不要求用户重新运行取数；没有界面能力或相应授权时，明确免下载交付未完成及所需处理，不编造链接。

1. **锁定现有批次**：核对已有HTML与SQLite的窗口、题库校验值、口径、完整性、实际国家范围；复用`shared_data`与现有模板生成共享HTML，校验不含原文、凭证或本机查询地址，保留来源SHA-256、批次manifest和共享件SHA-256。仅改分享元数据不得改变指标数值。源批失败或不完整时停止，不重跑refresh来修发布。
2. **人工核对目录**：在飞书网页读取完整目录，逐份打开已有看板或回执，按实际批次核对，不能仅凭名称/条数判断一致。旧文件无足够校验信息时标“无法确认一致”，不称复用成功。查重无法完成则停止。人工核对记录留在私有运行目录，不能注入伪造的CLI目录响应。
3. **先安全占位**：在批准目录上传不含业务数据的占位HTML，取得实际`/file/`链接；占位不当成看板。检查分享设置与协作者，先关闭链接和对外分享、限制仅管理员管理协作者。若飞书提示关闭对外分享将解除父目录继承，先展示**准确的新文件链接、将解除继承、要保留的管理员、最终公司内只读范围**，获得具体确认后才执行；保留管理员及已批准应用的必要访问，复查直接成员，不修改父目录或旧文件。
4. **原地填入本批共享件**：在该文件“更多→上传新版本”选择已校验HTML，保持相同文件token/链接；不创建同名正式副本，不直接上传本地原版。此网页路径已经实测可保留链接，不等于CLI原地覆盖在所有环境已验收。
5. **在线检查**：在飞书文件预览中测试市场/平台多选、日期/分组/标签交集、矩阵点击、页面切换、对照、图表、记录翻页、说明跳转及桌面/窄屏；记录筛选前后分子分母。下载该云端文件，核对SHA-256与上传件相同。`+preview`报`1060006`仅说明该API预览类型不可用，不能据此断言网页HTML不能交互；原文件回读用`drive +download --file-token <token> --output source`或获批网页“下载”。权限/下载失败仍须报告，不跳过完整性检查。
6. **按确认范围交付**：上述检查通过后，按当前具体授权开启“公司内获得链接的人可阅读”，再次核对对外分享关闭、协作者管理仅管理员、管理员访问保留。返回该文件真实预览链接＋同批简报，不返回文件夹/附件/下载地址代替。无需新增企业审核权限即可完成的界面操作不应描述成已经打通自动发布。

界面辅助发布的证据与程序`published`分开：若真实同事账号、外部拒绝或手机App尚未验证，逐项注明；用户已明确同意先交付时可给“界面辅助预览链接”，不冒充全部账号已验收，不填写`geo-accepted-*.json`或`last-success.json`为正式成功，不成为自动复用基线。完整账号验收后仍需按既有accept流程入账。失败不替换上一已验收入口；本次占位或待验收链接须显著标明状态。

单次补发布、修复权限和更新Skill均不恢复暂停的定时任务，不新建订阅。只有用户另行明确要求才变更任务；不能从“发布成功”推断定时链路已验收。

## 每次运行

运行者与查看者分开：运行 Skill 取数需要 Answerbit 品牌级只读 Key，由运行者安全提供或复用已安全配置的有效 Key，飞书发布连接另行授权；同事查看已生成的飞书看板，只需具备相应飞书访问权限，无需提供该 Key。Agent应从实际返回的文件URL交付，不能编造入口，也不能把文件夹、Agent附件或下载链接当作看板预览。仅本地导出成功不代表「免下载交付」完成；未通过时先写清缺项、处理人和下一步。

1. Agent 先告知需要品牌级只读 Key 和预计耗时（既有 1,000–3,000 条窗口可先估取数分析 3–8 分钟；在线题库、限流和飞书验收另计），安全配置前暂停。不要让用户把密钥写入对话。
2. 运行 `python3 geo_run.py <题库缓存.xlsx> <本地.sqlite> <本地看板.html> --market <已确认国家> [--begin 日期 --end 日期] [--excel 本地.xlsx]`。它调用现有真实只读刷新，必须读取配置的最新在线题库，完成匹配、计算和校验后才进入发布。Excel 默认只在本地生成。
3. 返回 `reused`：远端已验收清单与当前版本完全一致，且当前权限和源文件回读校验通过。交付 receipt.url 与 receipt.report，标注复用、原取数时间和本次核对时间。
4. 返回 `pending_acceptance`：只是安全上传的候选，不可当作已发布。Agent 在飞书打开候选；公司内模式先在具体文件权限变更获准后设置链接分享，再按下节实测并保存私有证据，再执行 `python3 feishu_publish.py <本地看板.html> <本地.sqlite> --accept-proof <私有验收证据.json>`。只有 `published` 才交付正式新链接及其 receipt.report。待验收链接可发给用户用于测试，但须明确不是发布成功；占位文件不得当作看板。
5. 飞书发布失败但本地数据校验通过：保留同批HTML及简报，明确`delivery_status=incomplete`，不能仅发附件结束默认交付。先一次列清连接/权限缺项；获准修复后只重试发布。停止后续写入，不换成功入口。说明具体环节、错误码、受影响窗口/指标和核查位置；有 previous 时列其窗口、原取数时间及链接，并说明本次是否核实访问；没有则明确无上一成功看板。不把候选地址、文件夹或本机路径冒充成功看板。

独立重试发布可运行 `python3 feishu_publish.py <本地看板.html> <本地.sqlite>`，不重新向 Answerbit 取数。源文件若有刷新失败状态则拒绝发布。此命令不绕过真实取数的 Key 门槛。

历史批次的分析口径与当前版本不符时，仅可标为历史交互预览，不能新发布为当前口径的正式看板；程序停止发布并要求刷新，保留上一成功入口。历史预览中的旧数值不得冒充本次实跑或当前口径简报。

## 版本与远端去重

`geo-publication/1` 使用窗口、品牌标识的 SHA-256、题库内容校验值、实际国家/平台/日期/分组/标签/点名状态、样本 ID 集合校验值、指标与推荐规则版本、计算数据库关键表、原始列表与逐条详情的校验值、平台汇总和渲染模板校验值。原始响应仅计算哈希，不复制进共享文件。原文虽只在本机，内容变化仍会改变版本。成功取数时间和纯刷新时间不用于强行产生新版本。

不能只比较名称、条数或 ID 集合。分享范围也须一致，管理员版本不能冒充公司内版本；不同范围使用独立候选及验收记录。目录须取全分页；遍历 `geo-accepted-*.json` 验收清单，核对清单结构/版本签名、真实文件权限与源文件 SHA-256。旧清单不完整、查重失败或匹配文件无法访问均停止，不猜相同版本。没有清单的旧 HTML 单列为历史文件，不复用，也不自动补造验收信息。旧 SQLite 缺完整来源指纹时需要刷新。

新内容先写不含业务数据的占位文件，确认链接分享关闭、外部访问禁用、直接及父目录成员均获批准后才原地填入共享 HTML；若平台默认组织内链接可读，只留下安全占位，返回权限问题。Agent 可按已授权的管理员范围收紧权限后重试；不得自动扩大授权、添加用户或绕过 CLI 高风险确认门槛。占位同名冲突、回读不符或中断都停止，不覆盖历史。

公司内模式仍先上传私有候选，通过共享字段与文件完整性校验后再按已确认的具体目标开放公司内只读。默认交付云空间文件预览链接与简报，HTML 下载仅为备用；消息附件、下载地址与 localhost 不能充当免下载交互入口。

## 逐版本预览与账号验收

验收证据必须由实际观察产生，不能预填通过。结构如下（布尔值仅在实测通过后改 true）：

```json
{
  "file_token": "实际候选标识",
  "html_sha256": "候选返回的完整校验值",
  "account": "实际登录验收账号",
  "checked_at": "实际带时区时间",
  "access_scope": "admins_only",
  "checks": {
    "market": false, "platform": false, "date": false,
    "group": false, "tag": false, "matrix": false,
    "navigation": false, "comparison": false, "charts": false,
    "metric_guide": false, "desktop": false, "narrow_screen": false,
    "permissions": false
  }
}
```

检查多选筛选及联动数值、国家×题类矩阵、页面切换、对照分析、图表、指标说明、桌面及窄屏。必须打开候选的飞书云空间文件链接，在预览视图内执行；Agent附件预览、下载链接、下载后本地打开和截图不算飞书交互验收。记录实际操作前后范围与样本量，零结果也应有明确提示。预览状态 READY 不证明交互。未通过时给功能限制与替代方式，保留上一成功版，不填 false 为 true。没有浏览器能力时报告待验收，不自动通过。

HTML须通过`feishu_delivery.shared_data`生成共享版并沿用模板，不由Agent临时重写、拆成依赖本机文件的多文件网页或将HTML转为图片/在线文档。模板在嵌入预览中直接处理页内导航，不依赖`delivery.mode`标记或改变外层页面地址；缺少标记不应导致分页失效，但不能因此跳过共享隐私校验。

无法交互时先区分：①筛选菜单能展开但页面切换失效，核对嵌入页导航兼容及模板版本；②页面或筛选根本未初始化，核对完整HTML、脚本报错、外部资源和文件大小；③只是附件/下载入口，改为获批云空间文件预览并重新验收。飞书官方目前说明HTML预览上限12 MB，部分风险功能受限，见[官方说明](https://www.feishu.cn/hc/zh-CN/articles/052565607602)。体积超限或当前客户端无法运行时，先报告限制；需要托管应用或管理员审批时先向用户报告，不公开上传内部数据。

公司内模式的证据使用 `access_scope: tenant_verified`，并增加 `operator` 对象：`account`、`checked_at`、`checks`（同上各检查项）、`external_account`、`external_denied`。另一位真实公司同事必须使用不同账号、无需单独协作者权限就能打开链接并操作；公司外身份须实际验证不能读取。任何一项未验证均保持待验收，不预填通过。企业策略禁止组织内分享时停止并报告，不转为互联网公开。

管理员账号通过不代表运营账号通过。`permissions` 包括文件和父目录的分享/成员复核，以及当前验收账号实际可访问。普通运营需另用真实账号测试应允许与应拒绝范围后，才能把 access_scope 写为 `operators_verified`。窄屏浏览器不代替飞书手机实机验收，两者分别报告。验收 JSON 是 Agent 的可追溯记录，不是平台签名，也不能代替实际账号测试。

验收命令再次读回源文件和权限，上传并回读已验收清单后才原子更新本机 last-success.json。所有检查均绑定同一版本及源文件 SHA-256。默认报告直接来自该验收记录，复用时保留原取数时间，避免报告与链接跨批。

## 原文、默认交付与失败

共享文件只含获准汇总、题文和定位字段，无原文、凭证、SQLite 或 localhost 查询地址。在 Answerbit 工作台 → 大模型回答记录，按题文、日期、平台和分组定位，飞书题库按题号定位。工作台入口不是单条原文直达链接。

默认返回飞书链接（复用/新发布）、3 项核心指标的分子分母、一段有依据且注明限制的判断、最多 3 条带证据的行动，并标窗口、取数时间、题库及指标版本。行动不足按证据数量展示。推荐仍是本地规则初判，未知不填零。Excel 默认不上传，需用户明确要求并确认适合共享。

取数/字段问题回 Answerbit；题号、题文、题库版本回飞书题库；目录枚举、上传、成员或分享问题回飞书文件/父目录及应用权限管理。程序不输出凭证或原始平台错误响应。

代码支持不等于本次连接可发布：CLI 缺少应用权限时先报告现有应用、缺项与影响，不自行扩权。可在用户授权的已登录网页进行一次试点上传与权限验收；未打通运行 Agent 的查重、上传及验收链路前，不声称自动发布已实测。

## 固定入口、更新频率与实际边界

官方 CLI 支持 `--file-token` 原地覆盖；本实现只用它填入**已验证权限的安全占位候选**，校验返回标识未变化。网页“上传新版本”已在一次获准试点中实测保持链接并回读SHA-256一致；CLI覆盖仍须在当前运行环境独立验证，不能互相代替。当前每个已验收版本保留独立链接。

固定入口的后续设计：单独使用只含“最新已验收看板”链接的入口文件；新版本验收清单写入并核对后，再更新入口，回读确认并在失败时恢复旧链接。该远端固定入口切换尚未实现，不能将本地 last-success.json 称为全公司固定入口。

当前按用户每次运行触发，无定时更新。发布需在同一个获批运行环境串行执行；不同机器并发发布没有分布式锁，可能出现同名冲突，程序会停止而不盲目覆盖。实际部署多人并发前需使用统一发布运行者或带条件写入的协调机制，不临时引入新服务。
