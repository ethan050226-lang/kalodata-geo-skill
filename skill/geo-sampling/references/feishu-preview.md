# 默认飞书交付：版本核对 → 复用 / 上传 → 验收 → 链接与简报

## 管理员一次配置

本节及`sharing_scope`用于严格自动发布；用户明确要求保留具体文件现有权限的单次交付，走下文[已有权限单次发布](#已有权限单次发布)，不擅自改写全局配置。

使用现有官方 `lark-cli`，不自建托管或数据库服务。Answerbit 品牌级只读 Key 与飞书身份授权独立，凭证保存在获批环境/钥匙串。私有环境配置 `GEO_QUESTION_BANK_URL`、必要时的 `LARK_CLI` 及 `GEO_FEISHU_CONFIG`（JSON 文件路径）。配置文件例：

```json
{
  "folder_url": "https://company.feishu.cn/drive/folder/FolderToken",
  "identity": "bot",
  "sharing_scope": "admins_only",
  "approved_members": [
    {"member_type": "openid", "member_id": "ou_approved_admin"}
  ],
  "state_dir": "/private/path/geo-publication"
}
```

只填实际批准管理员；identity可省略或留空，默认bot，既有user配置保持不变，无需向用户索要技术字段。精确匹配成员类型与 ID，不用姓名推断身份，不把群组/部门当作已验证的个人访问范围。普通运营账号未完成允许/禁止范围测试前，名单中不得加入运营范围。文件夹、成员 ID、旧成功链接等均只存私有配置，不提交公开仓库。可选 `previous_success` 保存有依据的旧入口、batch 及验收时间，**只作失败回退提示，不参与版本去重**。旧入口本次未核验时必须注明。

`sharing_scope` 默认 `admins_only`，保留旧配置行为；用户明确选择公司内共享后，可在私有项目配置设为 `tenant_readable`。此模式表示同公司登录并获得链接的人可阅读本批获准内容，不是互联网公开，也不是按国家隔离权限；筛选不能阻止阅读 HTML 内的其他已共享国家。首次变更须展示准确的新文件、当前与目标设置，确认后仅改该文件为组织内链接可阅读、禁止外部访问，不改父目录或旧版，不自动添加协作者。代码不静默修改分享权限。验收 JSON 清单仍只限批准管理员及应用，不能随看板开放。

常规发布使用中央登记记录及已知文件标识，不枚举目录，也不要求 `space:document:retrieve`。应用仅申请实际需要的文件上传/下载、权限设置读取及成员读取等权限；另核对获批目录的资源访问权；应用scope本身不等于只开放一个目录。需要企业管理员审批时，必须先按[权限申请前置报告](../SKILL.md#权限申请前置报告)向用户报告并等待决定，不自行申请或扩权。使用官方CLI在已批准的目录及接收范围内发布，不自动新增接收者或扩大分享。新建上传可能自动给当前 CLI 用户管理权，该用户也必须在批准名单内。

## 一次列清发布权限

先复用当前运行环境已有的获批连接，核对实际应用名称、app_id与bot/user身份（ID仅放管理员详情）。不要以Codex本机另一个应用的失败推断运行Agent缺权限。`lark-cli auth scopes --json`可只读查看当前应用权限；按当前CLI实际结构读取`scopes`/`userScopes`及`tokenType`，用户授权清单不能冒充bot权限。查询失败标未知，不能当作全部缺失。

使用官方[larksuite/cli](https://github.com/larksuite/cli)及其随附说明；原生调用前先看schema。启动时汇总下表全部能力，区分“已配置”“实际读通过”“缺失”“未验证”；只读探测不上传测试业务文件，不为确认权限而修改分享。可运行：

```sh
python3 feishu_publish.py <已有看板.html> <已有库.sqlite> --check-access
```

此命令不读Answerbit、不读取或改写批次、不列目录、不上传、不改权限；协作者和分享设置分别探测，一项失败也继续检查另一项。写入能力统一标未验证，须结合实际应用清单核对；读通过不证明上传或下载通过，也不证明中央记录已初始化。

| 能力 | 优先核对的最小权限 | 处理边界 |
| --- | --- | --- |
| 上传共享HTML/私有回执 | `drive:file:upload` | 本次实测免审，新增仍须用户确认。 |
| 下载原文件、核对SHA-256 | `drive:file:download` | 明确指定相对输出文件，避免为默认命名额外申请元数据权限。 |
| 读取直接及继承协作者 | `docs:permission.member:retrieve` | 文件与父目录分别核对；不把应用scope当资源共享权限。 |
| 读取分享设置 | `docs:permission.setting:read` | 核对实际链接范围与外部访问，不能只看上传成功。 |
| 修改分享设置 | `docs:permission.setting:write_only` | 仅用于已确认的具体新文件，父目录和旧版不改。 |
| 新文件保留管理员访问（按需） | `docs:permission.member:create` | CLI以bot新建可能尝试给当前CLI用户full_access；核对该用户在批准名单内，不转移所有者。 |

上表六项在此前后台实测免审，不保证其他租户或后续平台规则相同。目录扫描仅是管理员恢复历史的可选手段；确需 API 扫描时再单列 `space:document:retrieve` 及审批要求，不作为常规缺项。旧版CLI、导出权限核查或特定资源可能额外要求`docs:permission.member:auth`等条件权限：先核对CLI版本、官方错误和接口实际需要，单列原因与最小权限，再向用户报告；不能直接补全量权限。已有获批等价权限可复用，官方错误里的N选1不是全部都要申请。

官方 CLI 的[上传实现](https://github.com/larksuite/cli/blob/main/shortcuts/drive/drive_upload.go)另声明 `drive:drive.metadata:readonly`，用于上传后查询已知文件 URL；按部署版本及实际预检核对是否已有或需要，不误报为目录枚举权限。`--check-access` 将此能力标为未测试，不据此自动申请或声称已具备。

一次给用户“问题、影响、处理人、下一步”，管理员详情列最小scope、当前状态、官方入口、是否需企业审批（查不到写待核实）、资源范围及替代路径。应用未开通、用户未登录、文件未共享、工具/网络异常分开说明。需要企业审核的权限，在申请、扩权、提交审核或发布权限版本之前先报告并等待决定；仅允许免审时不提交审核项。免审不代表可无确认新增访问权。不要重复扫码、借用其他账号或改用`drive:drive`等宽权限绕过问题。

## 已有权限单次发布

这是已实测的 Agent 执行路径：**复用同批结果 → 核验现有连接与具体文件 → 原地上传 → 回读校验 → 飞书内交互验收 → 链接与简报**。使用现有官方 CLI、已获批原生接口或网页能力，不新建服务。严格自动发布继续按下文的 registry/stage/accept 执行；单次路径不冒充严格自动发布已完成。

1. **锁定同批结果和授权范围。** 新测量正常完成题库实读、Answerbit读取、国家模型裁剪及自检；仅补发布时直接复用已校验HTML/SQLite及已完成的总体、各国核心发现，不重新取数或触发采样。核对实际回答截止日、窗口、题库校验值、口径、范围及完整性。用`feishu_delivery.shared_data`和现有模板生成共享HTML；不含原文、数据库、凭证或本机查询地址。结论、行动和简报取同批数值；不把总体数量写到单一国家，不将范围外模型记成回答质量异常，不自行设健康阈值或猜测趋势。
2. **先复用已有连接。** 核对当前CLI版本、应用及bot/user身份。下载失败先看实际code/message：`drive +download`可能因额外导出权限检查失败，并不代表原文件不可下载。先用当前获批身份按官方schema测试`GET /open-apis/drive/v1/files/{file_token}/download`，读取完整文件字节；成功就复用，不申请`docs:permission.member:auth`、不重复登录。原生调用沿用受保护的现有连接，不把token拷进聊天、命令参数或日志，不绕过平台权限检查。接口确实缺权限才一次列清实际缺项及是否需企业审批，新增授权先确认。官方[下载实现](https://github.com/larksuite/cli/blob/main/shortcuts/drive/drive_download.go)已将部分辅助检查设计为可继续下载，部署旧版仍以实际响应为准，不能泛称所有CLI均有同一问题。
3. **锁定具体文件，防止重复创建。** 优先从私有发布记录取得获批目录、文件token/URL及上次内容SHA-256；核对实际文件名、内容、范围、协作者与分享设置。权限测试文本不是看板，旧HTML不是工具验收回执。未知内容或已有正式历史版本不覆盖；只更新获准的当前入口或本次占位候选。无可用目标时才在获批目录创建一次无业务数据的占位HTML，并立即保存返回token。`file_token=None`、超时或响应丢失表示结果不明：保留意图，停在原候选，从已有输出/登记或获准网页核查；不重传、不创建第二份、不以清空状态解决。网页核查不要求新增目录枚举API权限。
4. **按用户实际选择处理权限。** 默认沿用严格发布策略。若用户明确要求“上传但不改权限”，先记录该具体文件的链接范围、对外分享开关、协作者及批准范围：当前是组织内只读、成员均获准且授权涵盖本批共享内容时，按该授权上传，所有设置保持不变，不再次要求先改成`closed`。允许分享到组织外的开关不等于当前已向匿名互联网开放，仍须记录保留该设置的事实；单次决定不能自动扩大为其他文件、国家、环境或长期授权；已有持续项目授权明确覆盖本次同文件更新时直接复用，不重复确认。若实际公开匿名、出现外部/未知成员或范围冲突，先报告，停止相关上传。需要改权限时，列准确文件URL、当前和目标设置、是否解除继承及需保留成员，获得具体确认后才操作，不动父目录和旧版。不得修改`verify_file`或构造假回执来绕过严格策略。
5. **原地更新并回读。** 先按当前CLI帮助核对参数，在共享件所在目录执行已有上传能力；命令示意如下，所有路径相对当前目录，真实标识只来自私有配置：

   ```sh
   lark-cli drive +upload --file share.html --name GEO看板.html --folder-token <获批目录> --file-token <已锁定文件> --as bot --format json
   ```

   `--as`沿用实际获批身份，不默默换账号；新建时才省略`--file-token`。官方[上传实现](https://github.com/larksuite/cli/blob/main/shortcuts/drive/drive_upload.go)支持原地更新，运行时仍须确认返回token与目标一致。CLI不可用时，可在同文件“更多→上传新版本”更新，不能另发附件代替。下载远端完整原文件，验证字节数和SHA-256与本地共享件一致；前后回读权限，确认未发生未获准变更。校验失败不宣称成功、不写成功入口，保留旧成功版；同文件更新失败应报告该入口状态，不能保证未验证的自动回滚。
6. **实际打开飞书预览。** 打开返回的真实`https://<公司域名>/file/<token>`，测试市场/平台多选、日期/分组/标签、矩阵点击、页面切换、对照、图表、记录翻页、指标说明及桌面/窄屏，记录操作前后的范围和分子分母。国家核心发现必须随国家切换，不出现范围外模型；AIO无数据时比例显示不适用。`+preview`报`1060006`不代表网页HTML不能交互。只发附件、下载后本地可交互、READY状态或截图都不能代替此检查。没有浏览器能力时明确待交互验收，不预填通过；若无可用工具完成，说明处理人和下一步。
7. **交付链接并保存私有记录。** 回读及实际交互通过后，返回同文件链接、简短核心数据表、一段结论和有证据的行动；注明新上传/复用、单次手动交付、数据窗口、实际回答截止日、原成功取数时间和本次核验时间。私有记录保存文件token、获批目录、版本manifest、HTML SHA-256、报告、权限快照、用户授权依据、实际账号及各检查结果。未测的真实运营账号、外部拒绝和手机App单列，不把管理员或窄屏测试说成全员/实机通过。真实题库、数据、文件链接和记录不写入公开Skill或GitHub。

下次先核对同一已知链接、完整版本manifest、原文件SHA-256、当前权限及已有实际验收证据；全部一致且仍在获准范围时可复用这条**单次已核验链接**，标注原取数时间和本次核验时间，不重复上传或伪装新测量。证据不够就写明，不能仅凭文件名、条数或样本ID认定相同。内容变化时按批准的同文件更新策略执行；未获准覆盖现有历史版本时保留旧版并先说明。

**记录边界**：本路径的回读/交互证据与程序`published`分开；不伪造`geo-accepted-*.json`，不写`last-success.json`或严格`registry.json`为正式成功，不将部分账号验收冒充完整权限验收。严格入账仍需满足下文accept条件。缺严格回执不阻止用户已授权、权限已核验的单次上传，但不能因此忽略源数据失败、敏感字段或分享范围问题。

**定时任务继续暂停。** 单次补发布、修权限、更新Skill或上传成功均不新建、恢复任务；只有用户另行明确要求才变更调度。

## 每次运行

运行者与查看者分开：运行 Skill 取数需要 Answerbit 品牌级只读 Key，由运行者安全提供或复用已安全配置的有效 Key，飞书发布连接另行授权；同事查看已生成的飞书看板，只需具备相应飞书访问权限，无需提供该 Key。Agent应从实际返回的文件URL交付，不能编造入口，也不能把文件夹、Agent附件或下载链接当作看板预览。仅本地导出成功不代表「免下载交付」完成；未通过时先写清缺项、处理人和下一步。

1. Agent 先告知需要品牌级只读 Key 和预计耗时（既有 1,000–3,000 条窗口可先估取数分析 3–8 分钟；在线题库、限流和飞书验收另计），安全配置前暂停。不要让用户把密钥写入对话。
2. 运行 `python3 geo_run.py <题库缓存.xlsx> <本地.sqlite> <本地看板.html> --market <获准国家，可重复> --default-market <运营国家> [--begin 日期 --end 日期] [--excel 本地.xlsx]`。它调用现有真实只读刷新，必须读取配置的最新在线题库，完成匹配、计算和校验后才进入发布。Excel 默认只在本地生成。
3. 返回 `reused`：中央记录的版本与当前完全一致，且已知远端回执、看板权限和源文件回读校验通过。交付 receipt.url 与 receipt.report，标注复用、原取数时间和本次核对时间。
4. 返回 `pending_acceptance`：只是安全上传的候选，不可当作已发布。Agent 在飞书打开候选；公司内模式先在具体文件权限变更获准后设置链接分享，再按下节实测并保存私有证据，再执行 `python3 feishu_publish.py <本地看板.html> <本地.sqlite> --accept-proof <私有验收证据.json>`。只有 `published` 才交付正式新链接及其 receipt.report。待验收链接可发给用户用于测试，但须明确不是发布成功；占位文件不得当作看板。
5. 飞书发布失败但本地数据校验通过：保留同批HTML及简报，明确`delivery_status=incomplete`，不能仅发附件结束默认交付。先一次列清连接/权限缺项；获准修复后只重试发布。停止后续写入，不换成功入口。说明具体环节、错误码、受影响窗口/指标和核查位置；有 previous 时列其窗口、原取数时间及链接，并说明本次是否核实访问；没有则明确无上一成功看板。不把候选地址、文件夹或本机路径冒充成功看板。

独立重试发布可运行 `python3 feishu_publish.py <本地看板.html> <本地.sqlite>`，不重新向 Answerbit 取数。源文件若有刷新失败状态则拒绝发布。此命令不绕过真实取数的 Key 门槛。

历史批次的分析口径与当前版本不符时，仅可标为历史交互预览，不能新发布为当前口径的正式看板；程序停止发布并要求刷新，保留上一成功入口。历史预览中的旧数值不得冒充本次实跑或当前口径简报。

## 中央记录与版本去重

`geo-publication/1` 使用窗口、品牌标识的 SHA-256、题库内容校验值、实际国家/平台/日期/分组/标签/点名状态、样本 ID 集合校验值、指标与推荐规则版本、计算数据库关键表、原始列表与逐条详情的校验值、平台汇总和渲染模板校验值。原始响应仅计算哈希，不复制进共享文件。原文虽只在本机，内容变化仍会改变版本。成功取数时间和纯刷新时间不用于强行产生新版本。

不能只比较名称、条数或 ID 集合。分享范围也须一致，管理员版本不能冒充公司内版本。各国家状态目录内的私有 `registry.json` 保存强版本、已验收回执及其远端文件标识，并绑定目标目录；`last-success.json` 仍表示上一成功入口。常规流程只回读匹配版本或同品牌/国家/分享范围的上一版本及已知回执，不列目录。记录缺失、损坏、目标不符、旧入口不在历史中或已知文件不可访问时停止，不把未知历史当空目录，也不自动改用 API 扫描。

**首次接入或迁移**：管理员先实际核对获批目录的发布历史。使用已知 `geo-accepted-*.json` 的文件标识导入，程序会逐一回读版本、权限和 HTML 校验值；有旧 `last-success.json` 时，导入不能遗漏它。只有实际核对后确认没有工具管理的已验收回执时才允许空标识列表；已知手动HTML另存私有迁移记录，不声称无历史，也不伪装成工具已验收版本。未核对时停止初始化；已授权单次上传可走独立路径，不清空或覆盖旧记录。

管理员核查证明仅存私有文件，结构如下；`history_checked` 只有在实际核对后改为 true，账号/时间填真实值，不能由 Agent 预填通过：

```json
{"account":"","checked_at":"","history_checked":false,"receipt_tokens":[]}
```

```sh
python3 feishu_publish.py <同范围看板.html> <同范围库.sqlite> --initialize-registry <私有历史核查证明.json>
```

首次尚无看板时，额外提供 `--market <获准国家>`（可重复），看板与数据库参数可填计划文件路径，不要求先取数生成它们。该命令只初始化对应国家的中央记录，不读 Answerbit、不上传、不列目录、不切换成功入口或启用任务。初始化与发布均先用`scope_config`解析同一国家目录。优先使用此命令入口，不手拼低层调用：`initialize_registry(remote, state, proof)`的`state`是国家目录下的`last-success.json`文件路径，不是`state_dir`目录；把目录传入造成读文件错误，不能直接判为历史损坏。已有登记文件不自动覆盖；损坏时管理员从获批备份恢复。没有足够历史信息时保留待核查，不为出链接清空状态。迁移及恢复可通过已授权网页人工核对；仅在确有需要且另获授权时才申请目录 API 权限。

新内容先写不含业务数据的占位文件，确认链接分享关闭、外部访问禁用、直接及父目录成员均获批准后才原地填入共享 HTML。私有 `upload-*.json` 在上传前记录意图、收到响应后记录文件标识；已知标识时可回读并继续原候选，返回标识前中断则停止并要求管理员核对，不盲目重新创建。记录冲突、损坏或回读不符时不覆盖历史。若平台默认组织内链接可读，只留下安全占位，返回权限问题；不自动扩大授权或绕过高风险确认门槛。

公司内模式仍先上传私有候选，通过共享字段与文件完整性校验后再按已确认的具体目标开放公司内只读。默认交付云空间文件预览链接与简报，HTML 下载仅为备用；消息附件、下载地址与 localhost 不能充当免下载交互入口。

## 逐版本预览与账号验收

验收证据必须由实际观察产生，不能预填通过。结构如下（布尔值仅在实测通过后改 true）：

```json
{
  "file_token": "实际候选标识",
  "html_sha256": "候选返回的完整校验值",
  "account": "实际登录验收账号",
  "checked_at": "实际带时区时间",
  "access_scope": "admins_only",
  "checks": {
    "market": false, "platform": false, "date": false,
    "group": false, "tag": false, "matrix": false,
    "navigation": false, "comparison": false, "charts": false,
    "metric_guide": false, "desktop": false, "narrow_screen": false,
    "permissions": false
  }
}
```

检查多选筛选及联动数值、国家×题类矩阵、页面切换、对照分析、图表、指标说明、桌面及窄屏。必须打开候选的飞书云空间文件链接，在预览视图内执行；Agent附件预览、下载链接、下载后本地打开和截图不算飞书交互验收。记录实际操作前后范围与样本量，零结果也应有明确提示。预览状态 READY 不证明交互。未通过时给功能限制与替代方式，保留上一成功版，不填 false 为 true。没有浏览器能力时报告待验收，不自动通过。

HTML须通过`feishu_delivery.shared_data`生成共享版并沿用模板，不由Agent临时重写、拆成依赖本机文件的多文件网页或将HTML转为图片/在线文档。模板在嵌入预览中直接处理页内导航，不依赖`delivery.mode`标记或改变外层页面地址；缺少标记不应导致分页失效，但不能因此跳过共享隐私校验。

无法交互时先区分：①筛选菜单能展开但页面切换失效，核对嵌入页导航兼容及模板版本；②页面或筛选根本未初始化，核对完整HTML、脚本报错、外部资源和文件大小；③只是附件/下载入口，改为获批云空间文件预览并重新验收。飞书官方目前说明HTML预览上限12 MB，部分风险功能受限，见[官方说明](https://www.feishu.cn/hc/zh-CN/articles/052565607602)。体积超限或当前客户端无法运行时，先报告限制；需要托管应用或管理员审批时先向用户报告，不公开上传内部数据。

公司内模式的证据使用 `access_scope: tenant_verified`，并增加 `operator` 对象：`account`、`checked_at`、`checks`（同上各检查项）、`external_account`、`external_denied`。另一位真实公司同事必须使用不同账号、无需单独协作者权限就能打开链接并操作；公司外身份须实际验证不能读取。任何一项未验证均保持待验收，不预填通过。企业策略禁止组织内分享时停止并报告，不转为互联网公开。

管理员账号通过不代表运营账号通过。`permissions` 包括文件和父目录的分享/成员复核，以及当前验收账号实际可访问。普通运营需另用真实账号测试应允许与应拒绝范围后，才能把 access_scope 写为 `operators_verified`。窄屏浏览器不代替飞书手机实机验收，两者分别报告。验收 JSON 是 Agent 的可追溯记录，不是平台签名，也不能代替实际账号测试。

验收命令再次读回源文件和权限，先私有保存 `accepting-*.json` 待提交回执，上传重试沿用相同时间和字节；上传并回读私有已验收清单后，先登记中央历史，再原子更新 last-success.json。同版本同文件重复验收复用已登记回执，不重复上传；多文件写入不冒充系统级事务，异常停止并保留可核查状态。所有检查绑定同一版本和源文件 SHA-256；复用保留原取数时间。

## 原文、默认交付与失败

共享文件只含获准汇总、题文和定位字段，无原文、凭证、SQLite 或 localhost 查询地址。在 Answerbit 工作台 → 大模型回答记录，按题文、日期、平台和分组定位，飞书题库按题号定位。工作台入口不是单条原文直达链接。

默认返回飞书链接（复用/新发布）、3 项核心指标的分子分母、一段有依据且注明限制的判断、最多 3 条带证据的行动，并标窗口、取数时间、题库及指标版本。行动不足按证据数量展示。推荐仍是本地规则初判，未知不填零。Excel 默认不上传，需用户明确要求并确认适合共享。

取数/字段问题回 Answerbit；题号、题文、题库版本回飞书题库；中央记录问题由运行管理员恢复，上传、成员或分享问题回飞书文件/父目录及应用权限管理。程序不输出凭证或原始平台错误响应。

代码支持不等于本次连接可发布：CLI 缺少应用权限时先报告现有应用、缺项与影响，不自行扩权。可在用户授权的已登录网页进行一次试点上传与权限验收；未打通运行 Agent 的查重、上传及验收链路前，不声称自动发布已实测。

## 固定入口、更新频率与实际边界

官方 CLI 支持 `--file-token` 原地覆盖；本实现只用它填入**已验证权限的安全占位候选**，校验返回标识未变化。网页“上传新版本”已在一次获准试点中实测保持链接并回读SHA-256一致；CLI覆盖仍须在当前运行环境独立验证，不能互相代替。当前每个已验收版本保留独立链接。

固定入口的后续设计：单独使用只含“最新已验收看板”链接的入口文件；新版本验收清单写入并核对后，再更新入口，回读确认并在失败时恢复旧链接。该远端固定入口切换尚未实现，不能将本地 last-success.json 称为全公司固定入口。

当前按用户每次运行触发，无定时更新。中央登记仅适用于同一持久环境的单一串行发布者，须备份 registry.json、last-success.json、候选及上传记录。不同机器或外部人员绕过中央流程发布不会被自动发现，不支持多发布者并发；切换运行者先迁移完整状态并核对历史，再发布，不得从缺失记录自动起新库。定时仍须单次完整验收及用户明确要求后才启用。
