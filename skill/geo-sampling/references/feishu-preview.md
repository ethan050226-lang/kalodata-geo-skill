# 默认飞书交付：版本核对 → 复用 / 上传 → 验收 → 链接与简报

## 管理员一次配置

使用现有官方 `lark-cli`，不自建托管或数据库服务。Answerbit 品牌级只读 Key 与飞书身份授权独立，凭证保存在获批环境/钥匙串。私有环境配置 `GEO_QUESTION_BANK_URL`、必要时的 `LARK_CLI` 及 `GEO_FEISHU_CONFIG`（JSON 文件路径）。配置文件例：

```json
{
  "folder_url": "https://company.feishu.cn/drive/folder/FolderToken",
  "identity": "bot",
  "approved_members": [
    {"member_type": "openid", "member_id": "ou_approved_admin"}
  ],
  "state_dir": "/private/path/geo-publication"
}
```

只填实际批准管理员和应用身份；精确匹配成员类型与 ID，不用姓名推断身份，不把群组/部门当作已验证的个人访问范围。普通运营账号未完成允许/禁止范围测试前，名单中不得加入运营范围。文件夹、成员 ID、旧成功链接等均只存私有配置，不提交公开仓库。可选 `previous_success` 保存有依据的旧入口、batch 及验收时间，**只作失败回退提示，不参与版本去重**。旧入口本次未核验时必须注明。

应用仅申请实际需要的目录枚举、文件上传/下载、元数据、权限设置读取及成员读取权限；只授予目目录访问。需要企业管理员审批时，必须先按[权限申请前置报告](../SKILL.md#权限申请前置报告)向用户报告并等待决定，不自行申请或扩权。允许CLI读取题库不自动授权以CLI执行本页的发布操作，仍遵守用户对此类操作的限制。禁止用完整云盘授权绕过缺权限。新建上传可能自动给当前 CLI 用户管理权，该用户也必须在批准名单内。

## 每次运行

1. Agent 先告知需要品牌级只读 Key 和预计耗时（既有 1,000–3,000 条窗口可先估取数分析 3–8 分钟；在线题库、限流和飞书验收另计），安全配置前暂停。不要让用户把密钥写入对话。
2. 运行 `python3 geo_run.py <题库缓存.xlsx> <本地.sqlite> <本地看板.html> [--begin 日期 --end 日期] [--excel 本地.xlsx]`。它调用现有真实只读刷新，必须读取配置的最新在线题库，完成匹配、计算和校验后才进入发布。Excel 默认只在本地生成。
3. 返回 `reused`：远端已验收清单与当前版本完全一致，且当前权限和源文件回读校验通过。交付 receipt.url 与 receipt.report，标注复用、原取数时间和本次核对时间。
4. 返回 `pending_acceptance`：只是安全上传的候选，不可当作已发布。Agent 在飞书打开候选，按下节实测并保存私有证据，再执行 `python3 feishu_publish.py <本地看板.html> <本地.sqlite> --accept-proof <私有验收证据.json>`。只有 `published` 才交付新链接及其 receipt.report。
5. 失败：停止后续写入，不换成功入口。说明具体环节、错误码、受影响窗口/指标和核查位置；有 previous 时列其窗口、原取数时间及链接，并说明本次是否核实访问；没有则明确无上一成功看板。不把候选地址、文件夹或本机路径冒充成功看板。

独立重试发布可运行 `python3 feishu_publish.py <本地看板.html> <本地.sqlite>`，不重新向 Answerbit 取数。源文件若有刷新失败状态则拒绝发布。此命令不绕过真实取数的 Key 门槛。

## 版本与远端去重

`geo-publication/1` 使用窗口、品牌标识的 SHA-256、题库内容校验值、实际国家/平台/日期/分组/标签/点名状态、样本 ID 集合校验值、指标与推荐规则版本、计算数据库关键表、原始列表与逐条详情的校验值、平台汇总和渲染模板校验值。原始响应仅计算哈希，不复制进共享文件。原文虽只在本机，内容变化仍会改变版本。成功取数时间和纯刷新时间不用于强行产生新版本。

不能只比较名称、条数或 ID 集合。目录须取全分页；遍历 `geo-accepted-*.json` 验收清单，核对清单结构/版本签名、真实文件权限与源文件 SHA-256。旧清单不完整、查重失败或匹配文件无法访问均停止，不猜相同版本。没有清单的旧 HTML 单列为历史文件，不复用，也不自动补造验收信息。旧 SQLite 缺完整来源指纹时需要刷新。

新内容先写不含业务数据的占位文件，确认链接分享关闭、外部访问禁用、直接及父目录成员均获批准后才原地填入共享 HTML；若平台默认组织内链接可读，只留下安全占位，返回权限问题。Agent 可按已授权的管理员范围收紧权限后重试；不得自动扩大授权、添加用户或绕过 CLI 高风险确认门槛。占位同名冲突、回读不符或中断都停止，不覆盖历史。

## 逐版本预览与账号验收

验收证据必须由实际观察产生，不能预填通过。结构如下（布尔值仅在实测通过后改 true）：

```json
{
  "file_token": "实际候选标识",
  "html_sha256": "候选返回的完整校验值",
  "account": "实际登录验收账号",
  "checked_at": "实际带时区时间",
  "access_scope": "admins_only",
  "checks": {
    "market": false, "platform": false, "date": false,
    "group": false, "tag": false, "matrix": false,
    "navigation": false, "comparison": false, "charts": false,
    "metric_guide": false, "desktop": false, "narrow_screen": false,
    "permissions": false
  }
}
```

检查多选筛选及联动数值、国家×题类矩阵、页面切换、对照分析、图表、指标说明、桌面及窄屏。必须打开候选的飞书云空间文件链接，在预览视图内执行；Agent附件预览、下载链接、下载后本地打开和截图不算飞书交互验收。记录实际操作前后范围与样本量，零结果也应有明确提示。预览状态 READY 不证明交互。未通过时给功能限制与替代方式，保留上一成功版，不填 false 为 true。没有浏览器能力时报告待验收，不自动通过。

HTML须通过`feishu_delivery.shared_data`生成共享版并沿用模板，不由Agent临时重写、拆成依赖本机文件的多文件网页或将HTML转为图片/在线文档。模板在嵌入预览中直接处理页内导航，不依赖`delivery.mode`标记或改变外层页面地址；缺少标记不应导致分页失效，但不能因此跳过共享隐私校验。

无法交互时先区分：①筛选菜单能展开但页面切换失效，核对嵌入页导航兼容及模板版本；②页面或筛选根本未初始化，核对完整HTML、脚本报错、外部资源和文件大小；③只是附件/下载入口，改为获批云空间文件预览并重新验收。飞书官方目前说明HTML预览上限12 MB，部分风险功能受限，见[官方说明](https://www.feishu.cn/hc/zh-CN/articles/052565607602)。体积超限或当前客户端无法运行时，先报告限制；需要托管应用或管理员审批时先向用户报告，不公开上传内部数据。

管理员账号通过不代表运营账号通过。`permissions` 包括文件和父目录的分享/成员复核，以及当前验收账号实际可访问。普通运营需另用真实账号测试应允许与应拒绝范围后，才能把 access_scope 写为 `operators_verified`。窄屏浏览器不代替飞书手机实机验收，两者分别报告。验收 JSON 是 Agent 的可追溯记录，不是平台签名，也不能代替实际账号测试。

验收命令再次读回源文件和权限，上传并回读已验收清单后才原子更新本机 last-success.json。所有检查均绑定同一版本及源文件 SHA-256。默认报告直接来自该验收记录，复用时保留原取数时间，避免报告与链接跨批。

## 原文、默认交付与失败

共享文件只含获准汇总、题文和定位字段，无原文、凭证、SQLite 或 localhost 查询地址。在 Answerbit 工作台 → 大模型回答记录，按题文、日期、平台和分组定位，飞书题库按题号定位。工作台入口不是单条原文直达链接。

默认返回飞书链接（复用/新发布）、3 项核心指标的分子分母、一段有依据且注明限制的判断、最多 3 条带证据的行动，并标窗口、取数时间、题库及指标版本。行动不足按证据数量展示。推荐仍是本地规则初判，未知不填零。Excel 默认不上传，需用户明确要求并确认适合共享。

取数/字段问题回 Answerbit；题号、题文、题库版本回飞书题库；目录枚举、上传、成员或分享问题回飞书文件/父目录及应用权限管理。程序不输出凭证或原始平台错误响应。

## 固定入口、更新频率与实际边界

官方 CLI 支持 `--file-token` 原地覆盖；本实现只用它填入**已验证权限的安全占位候选**，校验返回标识未变化。未在真实租户完成覆盖回读前，不宣称稳定看板链接已经验证。当前每个已验收版本保留独立链接。

固定入口的后续设计：单独使用只含“最新已验收看板”链接的入口文件；新版本验收清单写入并核对后，再更新入口，回读确认并在失败时恢复旧链接。该远端固定入口切换尚未实现，不能将本地 last-success.json 称为全公司固定入口。

当前按用户每次运行触发，无定时更新。发布需在同一个获批运行环境串行执行；不同机器并发发布没有分布式锁，可能出现同名冲突，程序会停止而不盲目覆盖。实际部署多人并发前需使用统一发布运行者或带条件写入的协调机制，不临时引入新服务。
