# 国家定时推送

## 运行即配置订阅

默认由当前运行 Agent 执行自助配置，不要求用户另外写定时任务。只有用户明确只做单次分析/离线复盘时跳过创建计划；已有计划不因此自动取消。

1. **读取已有订阅。** 在获批的私有持久状态中，按运行 Agent、当前用户/租户、接收位置及“GEO 国家监测”用途定位稳定 subscription_id 与 scheduler_job_id。状态缺失时也先用原生调度器查重，不因换了聊天窗口就新建同类任务。归属不清时先核实，不能接管别人的任务。
2. **自动补齐明确参数。** 国家来源按“本次用户明确要求 → 用户已验证订阅 → 公司获准且已核实的人员国家表”解析，不从语言、IP、采样网络地区或同事名字猜。已指定者直接配置；未指定的检查时间默认每天北京时间 11:00（含周末），接收位置默认当前已验证的智能体会话。只有国家、接收身份或位置无法确认时，用一条问题收集所有缺项，例如：“请告诉我负责国家和接收位置；检查时间默认每天北京时间11点，需要调整可一起填写。”不重复询问已有可靠配置，不要求用户在聊天提供 Key。
3. **设置国家内容。** 仅纳入订阅国家，范围内平台/分组/标签默认全部；用户指定时取相应交集。按国家独立重算样本和指标；合并通知时也清楚分国展示。输出沿用已验收看板链接、核心数据表、结论和有证据行动，数据窗口默认前七个完整北京时间自然日。比较范围变化时建立新范围基线，不把旧范围差值当成新国家的变化。
4. **配置但不抢先启用。** 先保存国家、时区、检查时间、窗口、接收者、内容范围、指标版本、工具白名单和数据连接引用。安全凭证只保存获批的引用，不保存密钥明文。原生工具或数据、发布能力缺失时状态为 waiting_for_connector / waiting_for_validation，返回准确缺项；可以保存订阅草稿，但不能称已启用。真实取数仍按首次启动的 Key 等待规则。
5. **自动测试并登记。** 完成一次性定时投递测试、真实数据与发布校验、无更新静默及异常通知验证。纯文字投递测试禁用所有工具；若原生调度器支持，明确设置空工具白名单、关闭脚本模式并清除脚本，而不是用 shell 输出文字。只通过本人会话不能标其他运营通过；状态回读不暴露工具字段时注明证据不足，不伪造审计日志。测试计划与日计划分开，不把测试内容当报告。
6. **创建或更新计划。** 验证通过后，使用该 Agent 已具备的原生调度能力创建/更新并启用同一个任务。字段变化保留 subscription_id 和原 scheduler_job_id；用户另需独立订阅时才另外建立。回读时区、国家、接收目标、enabled/state 与下一触发时间。暂停任务即使仍显示旧 next_run_at 也不能称会运行。没有更新时静默，有变化且验收通过再发；异常按已验证路由通知。
7. **返回订阅回执。** 简洁列出负责国家、检查时间及时区、日期窗口、内容范围、接收位置、订阅/任务标识、创建或更新、当前状态、下一执行时间及验证结果。只有 active 才说“已启用”；未完成时说“订阅已保存，待接入/验证”，列出下一步。用户以后可说“改成美国，每天9点”“增加德国”“暂停推送”，Agent 修改同一订阅并重验受影响范围，不重复建任务。

以下是首次与重复运行的验收场景：

| 情况 | Agent 应做什么 |
|---|---|
| 已有已验证的国家、接收人和11点订阅，再次运行 | 回读并复用原任务，不重复追问或新建 |
| 用户说“只看美国，每天9点，发本会话” | 将当前订阅改为美国、09:00及当前已验证会话；重算并重验范围 |
| 用户未说明负责国家 | 一次询问国家与缺失的接收位置；时间用明确告知的默认值 |
| 国家与时间已保存，但没有 Answerbit 或上传原生连接器 | 保留待接入订阅，说明缺项，不启用报告任务、不调用CLI替代 |
| 一个接收者已送达，另一个未验证 | 明确部分通过，不把整组标为验证完成 |
| 用户仅要求本次离线分析 | 只做离线分析，不额外创建订阅 |

## 能力与授权边界

本 Skill 是运行规程，不是后台进程。先检查当前 Agent 有无持久原生调度器、无用户消息时执行能力、获批数据连接器、飞书看板发布/验收能力及主动发送到指定接收者的工具。逐项区分已配置、实测通过和待接入。不能把“已创建定时任务”说成“真实 GEO 报告链路已通”，不能用即时聊天回复代替定时主动推送测试。

用户明确禁止 CLI 时，调度和消息使用原生工具或飞书界面；数据读取与计算也不得偷偷调用终端/CLI。当前仓库 Python 流程依赖命令行，不能据此声称它已适配某个无 CLI 的飞书 Agent。只能使用该 Agent 已获批的等价连接器/计算流程；等价实现须按指标定义复核，否则通知数据链路缺项。不得另建 Codex 或其他平台定时任务代替用户指定的飞书 Agent。

“提示词写了禁止 CLI”不等于已在工具层禁用。无人值守任务应在支持的工作流或工具白名单中限制为获准原生能力；无法隔离时明确不能保证该约束，不宣称无 CLI 自动化已验收。发现 Agent 实际调用终端时立即停止该路径；不能恢复到受限原生工具集合的每日任务先暂停，保留任务 ID 与配置，不用终端读取调度文件绕过会话或工具限制。不同会话看不到同一任务时报告执行环境隔离，不猜任务不存在或另建重复任务。

定时运行沿用预先获批、安全配置的 Answerbit 品牌级只读凭证，不每天向聊天索取密钥。缺失、失效或越界时停止真实读取并异常通知。只读现有采样，不创建采样任务，不修改 Answerbit。飞书写入凭证独立管理，不把原文、凭证或原文数据库放进通知或共享空间。

## 一次配置与国家路由

首次确认执行 Agent、调度时区/时间、日期窗口、各接收者对应国家、身份、投递会话、共享权限与异常接收人。国家以实际题库及数据为准，不按网络地区猜市场。每个新运营自行确认其范围；不能把试点接收人复制成全公司的固定配置。

国家、接收人及路由作为私有运行配置，不提交公开仓库。可采用如下结构（字段值仅为结构说明，不是已配置数据）：

```json
{
  "timezone": "Asia/Shanghai",
  "local_time": "11:00",
  "days": "every_day",
  "window": "previous_7_complete_days",
  "subscription_id": "private_stable_subscription_id",
  "owner": "verified_current_operator",
  "status": "waiting_for_validation",
  "routes": [
    {"markets": ["CN", "US"], "recipient": "verified_recipient", "destination": "verified_agent_conversation", "verified": false}
  ],
  "scheduler_job_id": null,
  "last_success_by_scope": {}
}
```

若用户已指定国家和接收人，直接落实；只询问会改变结果且无法核实的信息。同一接收人可订阅多个国家，分别推送或合并为清楚区分的国家模块；不同范围分别过滤、计算和验收，不能把全量报告只改标题就推给单国运营。对同一会话及版本只投递一次。

不能仅凭同名联系人选择收件人。操作者与运营的双人私聊 ID，不能当作智能体与该运营的会话 ID。可使用已验证的智能体私聊，或仅包含获准人员和必要智能体的私有试点群；群接收范围必须与报告共享范围一致。未接通的接收者不得标记成功；明确部分送达，并向已验证的负责人通知缺项。不得自动扩大源文件访问权限。

## 默认每日行为

按用户确认的时区执行，每天含周末。每天 11 点的日报默认使用触发日 D 的 D-7 至 D-1 七个完整北京时间自然日，避免把未完成的当天混入完整日比较；在配置和报告中明确写出。用户若要求含当天，另行标注截至时刻，比较时遵守窗口可比规则。此规则不改变手动运行既有默认窗口。

1. 检查是否已有相同 Agent、范围、接收者与用途的任务，保存并复用任务 ID；编辑原任务，不重复建任务。记录执行环境、时区、下次触发时间与启用状态。
2. 读取最新获批题库和已有回答，按国家/平台/分组/标签对账并唯一匹配题号；按本 Skill 指标定义重算。点名题独立，提及率沿用未点名、扣除明确负面口径，不能因调度换用其他同名 GEO Skill 的旧公式。
3. 按各接收范围与上一次成功版本核对窗口、品牌、题库、范围、样本集合、指标版本及回答/判定、正式来源、口碑和状态关键内容校验值。只看数量或样本 ID 不能认定无变化。历史证据不足时说明无法判同，不伪造历史基线。
4. 无变化：保存检查状态，不发常规消息。有变化：数据完整性、题号、指标、共享权限和预览验收全部通过，才推送已验收看板链接及同批简报。原有发布验收门槛仍然适用；无人值守时无法实际验收新版则报“待验收”，不得预填通过。
5. 异常：通知已验证接收者及负责人，指出国家/窗口、失败环节、原因、受影响指标、上次成功入口与时间及核查位置。无旧版时明说没有。不能发布半批、占位或把旧版冒充新结果。因目标渠道本身失效而无法发送时，保留失败记录，并通过预先批准的可用备用渠道通知；没有备用渠道则明确不能保证异常通知。
6. 按接收者分别记录投递结果。单个收件人失败不重复给已送达人发送，后续补发仅针对失败者及同一验收版本。私有持久状态绑定任务、国家范围、版本、投递时间、结果和回查标识，不含原文或密钥。

## 默认通知

更新通知包含国家、窗口、成功读取及发布时间、题库与指标版本、已验收看板链接、3–5 项核心数据（分子分母）、一段事实与判断、最多 3 条有证据的行动。建议尽量附题号、题文、平台、日期与工作台核查方式；不把工作台首页称为原文直达。平台原值与 Skill 自算分开，不把推荐初判表述为人工确认。

异常通知保持简短且可行动：国家和窗口 → 失败环节与证据 → 旧成功入口/时间 → 回 Answerbit、飞书题库或权限管理核实哪一项。异常日志避免循环自触发和重复消息；恢复后说明恢复状态，不掩盖此前未送达的接收者。

## 必须实际验证

先创建一次性原生定时测试，约创建后 3 分钟向准确接收者发送明确标为“能力测试，非 GEO 报告”的短消息。返回任务 ID、实际触发时间、时区和接收者；触发前不得说已送达。触发后核对调度运行记录、结果、投递错误与实际目标会话中的消息。

分别验收：定时执行、本人接收、其他运营接收、更新后真实报告、无更新静默、数据/权限失败通知、发送失败回退与去重。只通过本人会话不能声称已推给其他运营。每个订阅配置版本只测试一轮，通过后不自动重复测试消息；关键路由或工具发生变化时重验相应部分。最终交付任务 ID、未来下一次执行时间、国家与收件范围、实测结果及缺项；尚未通过的数据链路和未接通收件人单列。

不同部署的原生调度器和消息工具并不通用。保留明确的工具适配边界，不承诺“任何 Agent 安装后都能主动推送”。
