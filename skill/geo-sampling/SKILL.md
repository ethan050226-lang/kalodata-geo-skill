# GEO 采样 Skill / GEO Sampling Skill

## 首次启动与凭证等待

Answerbit 固定使用 Kalodata 团队 `team_id=2117449160448806912` 和品牌 `brand_id=2117451182950580224`。Agent 启动每次真实取数或复检时，在同一个运行进程设置 `ANSWERBIT_BRAND_ID=2117451182950580224`，无需向用户索取这两个 ID。团队 ID 用于核对配置，当前回答读取接口只传品牌 ID。

每次准备真实取数或原文复检，先向用户说明需要只覆盖 Kalodata 的 Answerbit 品牌级只读 Key，并给出预计报告时间。首次且未配置凭证时可说明：「请在隐藏输入或本机运行环境配置 Kalodata 品牌级只读 Key，配置后告诉我。以最近一周、约 1,000–3,000 条记录为例，出看板预计约 3–8 分钟，平台限流会延长。」如果窗口更大或已有实际批量进度，按任务量更新估时。

**确认 Key 已通过安全方式提供前，暂停真实运行。** 在等待期间不启动取数、复检或生成结果；等待用户完成隐藏输入或确认已配置。用户回复已配置后先检查运行入口确实能读到凭证，仍缺失则继续等待。已有安全配置可直接使用，不要求重复提交。用户明确指定已有快照的离线复盘时，可走无需 Key 的快照入口。

## 默认输出看板

运行者提供品牌级只读 Key 后，从仓库根目录运行 `python3 dashboard.py refresh <飞书题库导出.xlsx> <私有目录/dashboard.sqlite> <私有目录/GEO运营看板.html> --excel <私有目录/GEO采样明细.xlsx>`。默认读取北京时间最近七个自然日的全部范围；指定日期时加 `--begin YYYY-MM-DD --end YYYY-MM-DD`。

**默认交付同一批次的三项结果**。

- 对话内给一份简短报告，按下文「默认报告」的核心数据表、结论与判断、优先行动项三部分交付。
- `GEO运营看板.html` 用浏览器打开，可离线筛选、对照和看图，无需启动查询服务。
- `GEO采样明细.xlsx` 用 Excel 打开。到「回答记录」按题号、日期、市场、平台、分组和标签筛选。「数据异常」列出已确认的飞书题号。缺市场标签时，可用同批已确认的 Answerbit 提问 ID 和相同题文补齐题号；证据不足时单列候选题号和待核查题文。这些记录仍按原口径判断是否纳入指标。回答原文留在本机数据库。

**对账范围是飞书题库和 Answerbit 返回题目的交集。** 正常回答和异常记录都使用已确认的飞书题号。没有题库候选的记录单独计数，不纳入指标和 Excel 明细，不阻止交付。只有题库内存在候选但题号无法唯一确认时，才保留上一批并交付题号待核对清单。按题文、任务 ID 和候选编号回飞书题库或 Answerbit 核对，勿用任务 ID 或占位符作题号。

在飞书等渠道支持附件且获准交付内部统计时，将两个文件作为当前用户可下载的附件或产物交付，逐项确认可访问。渠道无法交付附件时，仍给简短报告，并写明哪个文件无法交付及原因。只有文件确实在用户可访问的位置时才给出路径或下载入口。

**查询同批数据库时**，在获批本机的仓库根目录运行 `python3 answerbit.py query <私有目录/dashboard.sqlite>`，可离线读取指标和异常，可附 `--group-id` 与 `--tag-id`。查具体回答时，将同批 HTML 和 SQLite 保存在同一台电脑，运行 `python3 local_answers.py <私有目录/dashboard.sqlite> <私有目录/GEO运营看板.html>`，打开返回的本机地址，点「非明确推荐记录」的「查看原文」。查询期间保留该进程。数据库访问只读，无需 Answerbit Key。

每条通过校验并唯一匹配题号的有效回答按任务 ID 将题文和原文保存在本机 SQLite。HTML 只含统计与回查索引。含原文的 SQLite 和本机查询地址留在获批本机，勿通过飞书附件、GitHub 或对话转发。旧快照需重新取数才有原文。Answerbit 原生概览、趋势和引用排行使用各自的全范围快照，单独标明读取时间与范围；看板筛选重算 Skill 分析。刷新失败时保留最后成功数据，并在结果及旧看板顶部标明失败阶段。用户明确要离线复盘时可运行 `dashboard.py snapshot` 读取已有 SQLite，标注批次时间。

看板只显示当前分页。总览突出「提及率」、最值得核查的市场或题类的一段判断、2–3 条优先行动及数据状态，点名题独立展示，其他页分别承载平台快照、品牌表现、官网引用、回答表现、运营行动及对照分析。切页保留筛选和对照条件，平台页独立使用原生快照口径。

每次正式 `refresh` 都重新读取本次窗口的回答，首轮未知在同次运行自动用内存中的原文复检，通过对账后生成看板。用户明确要求补做历史快照的复检时，使用 `python3 dashboard.py review <题库.xlsx> <现有快照.sqlite> <现有看板.html>`。历史复检只重读首轮未知，保留该批首轮统计和平台快照。用户明确要求暂缓平台旧任务时加 `--defer-unavailable`。回答表现页展示合并后的推荐判断，非明确推荐表内的市场、平台、日期、分组、标签与顶部双向同步，可再筛推荐判断和待确认原因。对照分析逐条列出指标定义及差值，当前范围来自顶部筛选，对照范围在本页独立设置。

看板支持市场、平台、分组和标签多选。各筛选维度之间取交集，标签可选择匹配全部或任一。对照分析用独立条件重算两个范围，先展示关键差异，详细指标可展开，标注样本、分母、差值与重叠量。两组竞品集合一致时才比较提及份额。Answerbit 原生区沿用概览指标卡、品牌趋势和平台竞品排行的结构。

运营行动单独展示未点名题缺席、官网引用、首次位置、口碑和推荐判定中的可回查线索。每项按证据选择一个切片和代表题，区分现象、建议动作和复测口径。样本不足时提示先复核个例。

## 看板指标说明模块

每份 HTML 看板都须有独立的「指标说明」分页，离线可读。按样本与筛选、品牌表现、官网引用、推荐与口碑、Answerbit 平台快照与对照分组。每项按「看什么、怎么算、注意什么」组织，写清来源、分子、分母、去重、筛选、缺失和可比条件；指标卡链接到对应说明，平台返回值单独标注。定义以[指标定义](references/metric-definitions.md)为准，更新算法时同步更新看板说明和 Excel 对应字段。交付前核对指标分页可打开，说明与实际数值口径一致。

## 运行前

先读[指标定义](references/metric-definitions.md)。每次真实分析前确认凭证，并按用户需求确定分析范围。已提供的内容无需重复询问。

- 当前运行者在本机提供仅覆盖目标品牌的 Answerbit 只读 Key。交互终端支持隐藏输入，Agent 和其他非交互环境从当前用户的 `ANSWERBIT_API_KEY` 读取。密钥只通过本机的隐藏输入或环境配置提供，勿在对话、命令或报告中显示。缺少凭证或认证失败时停止真实分析。
- 用户未指定分组或标签时，相应维度按全部计算。指定一项时只筛该项，两项都指定时取交集。名称能从本地已核实的元数据唯一对应 ID 时直接使用；用户指定的名称有歧义或无法确认时，请用户提供 ID 或到 Answerbit「用户提问」核对。单个命令支持一个分组，选择多个分组时分开报告。

用户明确要求命令行指标或简报时，可调用 `python3 answerbit.py refresh <飞书题库导出.xlsx> <本地库.sqlite> --begin YYYY-MM-DD --end YYYY-MM-DD`。使用用户要求的日期窗，未指定时用北京时间最近七个自然日（含今天）并标注。题库使用已配置的全国家飞书题库导出。只读取现有记录，不触发采样或修改 Answerbit。真实输出使用独立路径，例如 `.trial/answerbit.sqlite`。

分析 `refresh` 返回的摘要。仅有回答记录时覆盖率未知，不把已返回记录当计划分母。合成试跑由独立的 `archive.py` 工具执行，与本 Skill 的真实取数入口分开。

分析品牌官网链接时读取 `website_links`，按 Kalodata、FastMoss 分别展示正文官网链接出现率和正式来源官网命中率，以及正式来源字段覆盖率。两项独立计算，同一回答可以各命中一次。用户要求分组或标签明细时，再使用 `website_links_by_group` 或 `website_links_by_tag`。旧快照没有该字段时先刷新。

完整内容指标报告读取 `content`，用 `dimensions` 按市场、点名状态及用户选定范围解释提及、份额与位置。推荐只看 Kalodata，始终单列「中立推荐」题单，按题号归并并保留每条回答的日期、平台和分组。在 Answerbit 用分组、题文、日期和平台回查，在飞书用题号回查。推荐初判注明规则版本、可判定覆盖及抽查状态；平台口碑仅用已核实的枚举映射，未确认时展示未知和平台原值分布。旧快照有 `content_status=需刷新` 时，刷新到新文件，旧快照可继续查询原指标。

## 默认报告

主指标统一命名「提及率」。只取 Answerbit 返回题文未点名 Kalodata 或审核别名的有效回答，在其正文命中分子中扣除平台明确负面，分母仍保留这些负面回答。保留褒贬并存和口碑未知命中。点名题另作品牌介绍、推荐及口碑分析。卡片列分子、分母和扣负面数量，详细规则从卡片跳转指标说明。平台快照标注「平台口径」，竞品全部正文命中与 Kalodata 的口径差异必须说明。

先标注数据窗口、成功取数时间、筛选范围和有效回答数，然后按顺序输出三部分。

1. **核心数据表**。选最能支持本次判断的 3–5 项数据，必须包含 Skill 自算的「提及率」，同时可采用可用的 Answerbit 平台快照，例如品牌提及率、平均排名、曝光效果分数。列为「指标、来源、本次、上次、变化」。Skill 比例写明分子和分母，平台没有返回分母时注明。比例变化用百分点，排名用名，分数用分；零分母显示不适用，未知显示暂无数据。
2. **一段结论与判断**。概括最重要的变化、涉及市场或题类，以及判断依据和必要限制。区分数据事实和运营推断。没有可比批次时只解释本次，避免给出增长结论。
3. **优先行动项**。最多三项，按重要性排列为 P1、P2、P3。有证据的项目不足三项时按实际数量输出。每项说明针对哪个市场、题类或平台，建议做什么、去哪里核实，以及下一轮如何同条件复测。涉及具体问题时附飞书题号、日期和平台。

**自动比较上次测量**。每次复用同一个获批的稳定输出位置，保留上一份成功 HTML 作为基线，失败尝试不成为基线。任务环境只提供临时目录时，先检查是否有权限取回上次产物；没有可读取的历史文件时明确说明无法自动比较。优先对比两次平台快照的同名指标，平台缺项时对比同口径 Skill 指标。首次运行或输出位置没有历史文件时说明无历史结果。题库版本、题目范围、分析口径或窗口长度不同或缺少历史范围证据时，并列数据并说明限制，不给直接变化结论。离线重绘同一批时沿用已有上次基线。自动对比按两批全量范围展示，与当前页面筛选分开；指定筛选范围的简报不能把整批差值当作该范围的变化。

市场、平台、分组和标签都保留为分析维度，默认只展示与结论相关的切片。合成测试显著标注。

## 选图

看板和用户另行要求的完整报告按分析问题选图。对话简报始终保留核心数据表。

- **折线图**用于同口径、同采样条件下至少两个可比轮次的时间变化。横轴用采样日期或轮次，缺样标为缺失。
- **柱状图**用于同一窗口内的平台、市场、题类或品牌写法对比。优先用环境内可用的标准图表工具。比较两项官网链接指标时按指标分组，每组并列品牌，使用相同的零起点百分比轴。柱端标出比例及各自的分子和分母，缺失值标为未知。条件不同则说明差异，避免把分组差异解释为市场或平台效果。
- **散点图**用于同一分析单元上两个数值指标的关系。每个点必须有一对可核对的数值，标明点代表什么，结论限于观察到的关系。
- **饼图或环形图**用于同一总体内互斥且完整的构成，标注总量和占比。可重叠的多标签、多个品牌提及率适合用柱状图。

从查询结果直接生成并展示图表，标明指标、筛选范围、时间和分母。发布前核对数值与快照一致，并预览检查图例、轴刻度和中文标签是否清晰、无遮挡。图里已展示的分组无需再附整表。没有合适的比较、趋势或构成数据，或图表无法可靠呈现时，用简表。

完整报告可按问题选图。竞品提及和份额图限定在相同竞品集合中。首次出现比例与平均名次分母不同，优先并排列表；推荐优先用分类表和中立题单。口碑映射未核实或覆盖不足时，只列可核对的数据。

Answerbit 的分组与标签是独立维度，飞书题库的分类也单独保留。用 `answerbit_groups` 和 `answerbit_tags` 分析平台分组及标签，区分标签 ID 和类型。用 `--group-id` 和可重复的 `--tag-id` 按交集筛选；未指定的维度省略参数。总体按唯一任务计数，同一道题可带多个标签。缺失或冲突的标签元数据标为未知。命令返回的异常清单覆盖整个取数批次，报告时区分所选范围内的问题和批次级问题。

日本品牌名对照先看题目使用的写法，再看回答使用的写法。按对应原题和日文品牌名变体配对，保留各自题号。仅比较题意一致且采样条件一致的对照题；整组汇总不能替代配对比较。旧口径没有日文拆分数据，需重新取数后才可用新口径对比。
