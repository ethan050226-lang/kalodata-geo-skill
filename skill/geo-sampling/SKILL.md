# GEO 采样

统一 Agent 接收需求，由获批中央环境执行。默认交付可在飞书内直接交互的看板链接和同批简报。取数由运行者提供或复用安全配置的品牌级只读 Key；同事查看已发布结果只需相应飞书访问权限。

## 执行入口

先确认本次目的和运营国家。对话中已确认的直接沿用，历史国家配置须确认。按管理员批准的国家和接收人映射交付，自报国家不能扩大可见范围。

| 用户要什么 | 从哪里开始 | 完成条件 |
| --- | --- | --- |
| 看已有结果 | 核对范围、已验收版本和链接访问 | 返回原窗口、成功更新时间、链接及同批简报 |
| 测一次最新数据 | 在完整仓库根目录运行下方命令 | 完成当批分析，再按飞书发布结果继续 |
| 只要本地看板 | 相同命令加 `--local-only` | 写入同批核心发现后交付本地看板与简报 |
| 补分析或补发链接 | 复用已校验的 HTML 和对应数据库，缺分析先写入，随后运行 `python3 feishu_publish.py <看板.html> <库.sqlite>` | 不重取 Answerbit 或题库；按实际权限与预览结果交付 |
| 复盘历史 | 纯离线重绘用 `dashboard.py snapshot`；仅查指标用 `answerbit.py query` | 标明原批次。补读平台快照或在线 review 须先核对最新题库 |
| 设置推送 | 按[集中执行与国家推送](references/scheduled-delivery.md)确认国家、接收位置、时间及时区 | 推荐每周一北京时间 11:30。先保存订阅草稿；现有定时任务继续暂停，单次验收后仍需用户明确要求才启用 |

```sh
python3 geo_run.py <题库缓存.xlsx> <同批库.sqlite> <看板.html> --market <国家代码> --excel <本地明细.xlsx>
```

占位符替换为获批私有路径和实际国家，多国重复传 `--market`。只读取已有回答，不创建计费任务。手动、定时窗口及管理员配置见[运行命令](../../README.md#运行命令)。`--check` 和单独读取题库仅用于诊断，正常刷新已包含实读。告知运行者预计耗时，按实际任务量与限流更新。

## 刷新与分析

1. **实读题库。** 安全取得有效 Key 后查私有品牌配置。刷新入口先用既有飞书只读连接校验完整国家页、修订一致性、题号及内容校验值，再分页读取 Answerbit。题库不可读或不完整时停止，Answerbit 请求为零。首次接入、换身份或读取失败时查[题库连接](references/feishu-connection.md)。
2. **匹配和筛查。** 国家取自唯一匹配的题库工作表与题号。正常与异常均匹配；无候选单列，有多个不能确认的候选时停止发布。原文按[指标定义](references/metric-definitions.md)筛查：报错、截断或有缺项证据的缩水回答标为数据异常，剔出有效分子和分母。仅长度下降单列待核查。保留正常短答、未知口碑与异常的区别。
3. **裁剪国家。** 按[国家与模型配置](references/country-models.md)从私有母批生成独立副本，从同一副本重算看板、简报、Excel 和比较。核查内嵌数据、模型和筛选选项均在授权范围内；只预选国家不能隔离数据。无样本的平台保留对应状态，零分母显示「不适用」。Answerbit 分组、标签和飞书分类分开，按[运营场景](references/analysis-scenarios.md)解释。
4. **写核心发现。** 结果中有 `local.analysis_context` 就复用它。按[核心发现分析](references/core-findings.md)分别分析总体及各国，执行 `core_findings.py apply`，使用返回的同批简报。筛选后的样本集合不同，只复用完全对应的分析。按[看板展示规范](references/dashboard-design.md)把方法放「指标说明」、异常放「数据提醒」，保留数字、分母、时间和具体行动。

## 飞书交付

| 运行结果 | Agent 的下一步 |
| --- | --- |
| `local_ready_pending_analysis` | 继续完成核心发现，按本次本地或在线交付要求收尾 |
| `local_ready_pending_publication` | 先完成尚缺的分析，一次说明发布缺项。修复后仅发布同批结果 |
| `pending_acceptance` | 核对远端文件、访问范围及真实预览交互，按[逐版本验收](references/feishu-preview.md#逐版本预览与账号验收)提交该版本证据 |
| `published` 或 `reused` | 返回已验收链接与同批简报，说明新发布或复用。复用时另标本次核对时间 |
| 已获准对指定文件单次更新 | 按[已有权限单次发布](references/feishu-preview.md#已有权限单次发布)核对现有分享范围，原地更新共享版，回读比对并打开飞书实测。单独记录该次结果 |

常规查重使用私有登记及已知文件，校验题库、范围、窗口、样本、关键内容和口径；登记恢复见[中央记录与版本去重](references/feishu-preview.md#中央记录与版本去重)。上传结果不明先找回原文件。只上传获准的共享版，Excel 和含原文数据库留在本地。凭证、内部地址、私人配置和真实交付物不得提交 GitHub。

实际飞书预览须验证筛选、矩阵、翻页、对照、指标说明及目标账号访问。附件、本地打开和管理员预览不能代替目标账号验收。失败时说明「免下载交付未完成」、环节、影响和处理人；有已记录的上次成功链接就附原窗口、更新时间及本次可访问性，无记录则明说。保留上次成功记录。

## 权限申请前置报告

优先沿用现有获批身份与权限，Answerbit 和飞书凭证分开。需要新增权限时先说明具体权限、用途、资源范围、现有授权不足的证据及替代方案；新增免审项也先确认，企业审批准许后方可提交。按[发布权限清单](references/feishu-preview.md#一次列清发布权限)一次列清缺项。品牌和题库地址从获批私有配置读取，聊天中不收集密钥。

## 简短报告与上次对比

- 列窗口、国家与筛选范围、有效样本量、最后成功取数时间、题库及指标版本。核心表放 3–5 项，数字旁列分子、分母和单位。
- 主指标名为「提及率」。分母为未点名题有效回答数，分子为正文命中且平台未判明确负面的回答数，同时展示扣除数。点名题单列，平台快照标「平台口径」，竞品按全部正文命中。缺失不填零。
- 用一段话写哪里、什么指标、多少及下一步，最多列三条有证据的行动，附题号、题文、日期、平台和回查入口。证据不足写具体待核查项。工作台链接仅用于定位。
- 题库、题目范围、口径、窗口长度及来源可比时才给变化。整批历史和平台原值各标独立范围，只有同条件历史才能展示筛选后的变化。
